    The problem

    Servo software, stepper hardware

    The ROBOTIS OpenMANIPULATOR-X stack is a complete ROS 2 arm application, but it expects DYNAMIXEL smart servos that answer Protocol 2.0 from their Control Tables. The BCN3D Moveo is a printed arm with NEMA stepper motors and no bus at all. Porting the ROS side to every new arm is expensive, so SmartManipulator-X moves the adaptation into a controller that looks like DYNAMIXEL servos to the host.

    Keep the ROS 2 stack unchanged

    The SmartFusion2 answers as virtual DYNAMIXEL devices: six stepper axes (IDs 1–6), the gripper servo (ID 7) and a controller device. The simulation firmware passes the protocol conformance check, 49 of 49, on native_sim.

    Quick start

    The Robot PC in simulation, in two commands¶

    No board and no arm are needed: the Robot PC runs ros2_control with mock hardware in Docker, on a network that stands in for the Ethernet link to the Operator PC. A second container on the same network checks it over ROS 2 DDS.

    git clone https://github.com/SystemFromScratch/sfs-smartmanipulator-x-robot.git
cd sfs-smartmanipulator-x-robot

docker compose -f docker/docker-compose.yml up --build robot_pc                 # terminal 1: the Robot PC
docker compose -f docker/docker-compose.yml run --rm probe smx_smoke_test.sh    # terminal 2: a second host

    The smoke test passes when it receives /joint_states, finds the joint_state_broadcaster, arm_controller and gripper_controller active, and arm_controller executes a short trajectory. In VS Code, Ctrl+Shift+B offers the same steps as tasks (Getting started).
